# Caeser v8 — investigation handoff and failure-matching fixes

v8 includes the fixes made after v7 and remains a prebuilt Linux amd64 release.
The setup action, reusable workflow and `caeser init` now default to v8.

## Changes since v7

- Explicit runtime probing can fall back to exact localized implementation
  functions when SSA, implementation stack frames and coverage supply no
  operation. Returns are tried across a bounded set of functions, with
  `localized_function_hypothesis` recorded as the selection reason.
- Sequential native Go test output can preserve a named failing check across
  probe repetitions without requiring a Testify `Test:` label. GitHub job-log
  prefixes are recognized. Parallel and ambiguous native streams abstain.
- Testify matching requires the exact numeric source line and an unambiguous
  named check. Line 70 cannot satisfy a check at line 7.
- Identical copies of a whole CI log stored in multiple report fields no longer
  make one assertion look repeated. Repeated assertions within a log remain
  ambiguous.
- Assertion labels are distinguished from identifiers such as `actual_test.go`
  and `unexpected`; empty values are not substituted from the next log line.
- Optional repository-owned GitHub Apps can author PR comments. Only the
  publishing job receives the App key, and comment updates match the
  authenticated App's identity. Registration, installation and credential
  configuration are still required.
- The README and architecture guides describe source analysis, execution
  orchestration, Docker boundaries, model retrieval, investigation state and
  caching in detail.

## Use v8

For automatic PR reports, update the caller's reusable workflow reference:

```yaml
uses: caeser-org/ceaser/.github/workflows/ci-diagnose.yml@v8
```

If you explicitly set `caeser_version`, set it to `v8` too. Existing workflows
pinned to v7 keep using v7. New callers generated by `caeser init` use v8.

For a custom job that only needs the CLI installed:

```yaml
- uses: caeser-org/ceaser@v8
- run: caeser version
```

See [CI integration](https://github.com/caeser-org/ceaser/blob/v8/docs/ci-integration.md)
for setup and custom App authors, and
[architecture](https://github.com/caeser-org/ceaser/blob/v8/docs/runtime-architecture.md)
for execution behavior.

## Validation and limits

Regression tests exercise the fallback with a real compiled Go test binary:
an unused candidate is tried first, a later function produces the observed
value, and the original failure is preserved across three runs. Adversarial
tests reject wrong locations, ambiguous checks and unsupported causal claims.

These checks do not establish a new public-corpus root-cause success rate. The
last frozen 16-case probe evaluation verified zero mechanisms; it has not been
rerun with these changes. Runtime probing remains opt-in and experimental, and
source-only observations cannot satisfy the strict SSA mechanism proof gate.
The normal PR report remains useful when a mechanism is unresolved.

Assets: `caeser_linux_amd64`, `SHA256SUMS` and `BUILD_INFO.txt`. The binary is
built on Ubuntu 24.04 with CGO/glibc; other platforms require a compatible source
build. Caeser itself is built once per release. Target test compilation remains
a separate cost.
