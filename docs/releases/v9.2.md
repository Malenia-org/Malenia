# Ceaser v9.2 — evidence-ordered leads and actionable comments (proposed)

v9.2 is a diagnostics-quality release. It does not change the Go adapter, the
probe/verification gates, or the root-cause promotion rules. It makes the
existing evidence easier to act on: the likely-function shortlist now respects
the candidate tier's own evidence order instead of a coarse provenance bucket,
the bounded candidate report no longer lets the failing test file crowd out
implementation candidates, and the PR comment shows the concrete failure text
and the primary suspect.

This release is **not published**. It is prepared for review.

## Changes

- **Evidence-ordered likely-function ranking.** The shortlist preserves the
  candidate tier's rank and promotes operand-correlated SSA leads
  (functions on the failed assertion's operand dependency path, labelled as
  leads, low confidence). Observed stack frames are ordered ahead of
  runtime/testing/dependency frames. Root-cause promotion, confidence semantics
  and abstention are unchanged.
- **Candidate report is a developer handoff.** Implementation candidates are
  kept ahead of `_test.go` entries before the report limit, so the failing test
  file cannot displace them.
- **Concrete failure text.** The panic/exception line is extracted from Go test
  output and generic runtime-exception text, instead of the placeholder
  "runtime exception or panic was reported". The GitHub Actions log prefix is
  handled.
- **Actionable PR comment.** The comment leads with a **Primary suspect**, then
  **Other ranked leads**, then **What to investigate** from the report's
  existing `next_actions`, with the unverified disclaimer retained.

## Validation (frozen 16-case Go corpus)

Ranking stage, saved reports, identical inputs (see
`cmd/likely-bench/README.md`):

| Metric | Before | After |
| --- | ---: | ---: |
| Top-1 (function) | 5 | 8 |
| Top-1 (function or file) | 7 | 9 |
| Misleading primary | 7 | 5 |
| Coverage | 14/16 | 14/16 |

Candidate-report selection (`--rebuild-candidate-report`): candidate recall
9→11 (function), top-1 9→10, top-3 11→13, coverage 14→16, non-stack top-1 3→4;
misleading primary 5→6. The precision rate is approximately flat
(35.7%→37.5%); the extra misleading case (`go-u004`) is a cross-package scope
limitation documented in `evaluation/discovery-findings.md`.

Held-out check (gin, koanf): gin top-1 `tree.go node.getValue`; koanf top-3
`koanf.go toFloat64`. No regression observed, n=2.

## Not in this release

- Mechanism A (function admission depth) and mechanism C (dependency-package
  indexing scope) are investigated and documented, not shipped: they cannot be
  validated end-to-end against the frozen reports (fixed snapshots) and risk
  noise/cost without that validation. See `evaluation/discovery-findings.md`.
- No verified-mechanism or root-cause behavior changed. No capability is claimed
  that has not been validated.

## Curated demos

Six curated demos were run through the source-built engine
(`evaluation/demo-prs/`): a panic, an assertion whose culprit is absent from the
stack, a deeper call chain, a conversion regression, a data race (abstention)
and an SSA-dependency case. Four of six produced the correct primary suspect;
one (koanf `toFloat64`) is a documented ranking limitation, not a regression.
Beyond-stack localization is demonstrated by the SSA-dependency demo
(`mcp/tools.go GetInt`).

## Toolchain note

The release toolchain is pinned to **Go 1.26.11**. `govulncheck ./...` reports
**0 called vulnerabilities** on that toolchain (2 in required modules that are
not called); the previously used toolchain reported 22 standard-library
advisories.
