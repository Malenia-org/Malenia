# Ceaser v9.1 — localization crash fix

v9.1 is a small patch release on the v9 likely-function line. It keeps the v9
behavior and fixes a crash in source localization. The setup action, reusable
workflow and `ceaser init` now default to v9.1.

## Fix

- Frames whose line was only covered by a whole-file node (no enclosing symbol)
  selected that `File` node as the enclosing symbol. Candidate creation skips
  file/dependency nodes, so the follow-up provenance write dereferenced nil and
  crashed the diagnosis. File and dependency nodes are no longer eligible
  enclosing symbols. A regression test covers the case.
- Observed on a Go data-race corpus case whose stack frame matched a file
  without an enclosing symbol; the case now completes instead of panicking.

## Use v9.1

For automatic PR reports, update the caller's reusable workflow reference:

```yaml
uses: caeser-org/ceaser/.github/workflows/ci-diagnose.yml@v9.1
```

If you explicitly set `ceaser_version`, set it to `v9.1` too. Callers pinned to
`v9` keep using the v9 release.

For a custom job:

```yaml
- uses: caeser-org/ceaser@v9.1
- run: ceaser version
```

## Validation and limits

Full `go test ./...`, `go vet ./...` and the localized package race tests pass.
The Go corpus was diagnosed end to end with the patched binary: all 15 cases
produced reports and none crashed, with culprit-file localization in 10/15
cases. That localization rate and the previously documented limits are
unchanged; this patch does not add verified mechanisms.

Assets: `ceaser_linux_amd64`, `SHA256SUMS` and `BUILD_INFO.txt`. The binary is
built on Ubuntu 24.04 with CGO/glibc; other platforms require a compatible
source build.
