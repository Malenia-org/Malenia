# Caeser v9 — likely-function handoff

v9 keeps the v8 evidence-first diagnosis engine and adds a developer-facing
likely-function tier. It remains a prebuilt Linux amd64 release installed by
checksum-verified download.

## Changes since v8

- Adds a structured `likely_function` field with one primary suspect, ranked
  alternates, reason, confidence, provenance kind, and evidence IDs.
- Ranks observed stack leads and exact SSA dependency values above generic
  inferred call leads. A public controlled case now points to
  `mcp/tools.go:255 GetInt` from SSA evidence when probing is disabled.
- Keeps the candidate report and PR comment shortlist, and adds a dedicated
  “Likely function to inspect” section with explicit notice that leads are not
  verified root causes.
- Adds an experimental direct numeric-cast proof path for Testify assertions.
  Public validation did not establish a verified mechanism, so the existing
  promotion requirements remain unchanged.
- Controlled harness can install a published release binary by tag with
  checksum verification.
- Removes stale generated outputs and the committed gateway binary.

## Use v9

For automatic PR reports:

```yaml
uses: caeser-org/ceaser/.github/workflows/ci-diagnose.yml@v9
```

For a custom job:

```yaml
- uses: caeser-org/ceaser@v9
- run: caeser version
```

## Limits and validation

The 16 sealed Go cases still show zero verified mechanisms. The likely-function
tier is a localization and handoff aid, not root-cause proof. Its reviewed
top-1 function hit rate on the sealed cases is 6/16, up from 5/16 before the
provenance and SSA ranking changes. Full Go tests, vet, build and formatting
checks pass.

Assets: `caeser_linux_amd64`, `SHA256SUMS`, and `BUILD_INFO.txt`.
